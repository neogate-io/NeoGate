方案对比

大模型 API 网关方案怎么选？

选择网关时，关键不是功能清单越长越好，而是它是否匹配你的部署边界、接口兼容、 访问隔离、用量统计和计费需求。下面是一份中性的选择清单。

选择清单

在共享模型访问之前，先确认这些问题。

部署模式

网关能否运行在你自己的基础设施里，还是模型流量必须离开你的环境？

接口兼容

你的客户端需要 OpenAI 兼容接口、Anthropic 兼容接口，还是两者都需要？

运维控制

管理员能否管理上游通道、凭证、路由、健康状态和访问策略？

项目隔离

团队、应用或客户能否获得独立 API Key，并独立归集用量？

用量和成本

能否按用户、项目、API Key、模型、供应商和上游通道查看用量？

计费准备度

是否需要余额检查、模型价格、充值流程，以及走向付费模型服务的路径？

适合场景

什么时候适合 NeoGate？

  • 你希望为多个模型供应商提供一个私有化统一入口。
  • 你需要发放项目 API Key，而不是共享上游供应商密钥。
  • 你关心项目、API Key、模型和通道维度的用量记录。
  • 你需要内部成本归集，或计划提供付费模型调用服务。
  • 你偏好 Rust 后端和简单的 Docker Compose 部署。

非目标场景

什么时候可能不适合？

  • 你只需要一个很小的本地开发代理。
  • 你完全不想维护任何基础设施，只想使用托管服务。
  • 你的主要需求是 Prompt 评测、Prompt 管理或 Agent 工作流。
  • 你已经深度绑定某个云厂商 AI 网关，并且不需要可迁移性。
