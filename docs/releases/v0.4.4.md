## NeoGate v0.4.4

NeoGate v0.4.4 is a patch release focused on Responses API compatibility, reliable image and video workflows, quota-aware upstream failover, prompt-cache affinity, and installer reliability.

### Highlights

- Added `/v1/responses/compact` support, corrected compact-request output limits, improved Responses streaming and fallback diagnostics, and normalized leading `<thinking>...</thinking>` or `<think>...</think>` content into reasoning output for both native Responses and Chat Completions fallback responses, including tags split across stream chunks or preceded by whitespace.
- Improved asynchronous image generation and editing with durable request spooling, correct JSON and multipart request encoding, clearer upstream error diagnostics, stale-task cleanup, and support for Responses image edits with reference images.
- Added HaxiCloud Seedance video routing, fixed decorated video model matching, and exposed richer video usage and billing dimensions in the admin usage view.
- Recorded image-generation token usage and preserved streamed prompt-cache usage so usage reports and billing remain accurate across image and streaming requests.
- Classified exhausted upstream quotas consistently, returned non-retryable insufficient-quota errors when appropriate, introduced a configurable quota cooldown, and improved retry and SSE failure diagnostics.
- Improved Claude Code prompt-cache affinity across OpenAI Responses and Anthropic Messages requests, including Redis-backed affinity for distributed deployments without storing raw affinity values in cache keys.
- Refreshed model pricing data, fixed provider pricing aliases, and added support for nested model cost records.
- Hardened operational behavior by applying upstream timeouts consistently, raising the default per-user concurrency limit from 10 to 100, simplifying low-level configuration, and defaulting trusted proxy-header handling for the standard reverse-proxy deployment model.
- Improved generated installers with HTTP redirect handling, corrected Node.js LTS metadata parsing, system package-manager installation for Node.js, and Windows PowerShell fixes.
- Updated backend, scheduler, and frontend version metadata to `0.4.4` so runtime checks and build artifacts report the same release.

### Upgrade Notes

- No new database migration is included in this release. Deployments upgrading from v0.4.3 can reuse the existing schema.
- Rebuild and deploy the backend, scheduler, and frontend together so API behavior, background-task processing, pricing data, and version metadata remain aligned.
- `TRUST_PROXY_HEADERS` now defaults to `true` because the standard deployment runs behind a trusted reverse proxy. Set it to `false` when exposing the backend directly or when requests can reach it through an untrusted proxy.
- Several low-level tuning environment variables were removed in favor of fixed operational defaults. Compare custom deployment configuration with the updated environment examples; notably, the default `USER_CONCURRENT_REQUEST_LIMIT` is now 100 and `QUOTA_COOLDOWN_SECONDS` defaults to 600 seconds.
- Asynchronous image requests may spool request bodies under `NEOGATE_ASSET_DIR`. Ensure this directory is writable and has sufficient disk capacity, especially for image edits with multiple or large reference images.
- Distributed deployments should continue using a shared Redis instance so prompt-cache affinity can be honored across backend instances.
- Upstream quota exhaustion and retryability are classified more precisely in this release. Review monitoring and client-side retry policies if they depend on previous generic 429 or 5xx behavior.
- If you use the generated installer, redistribute the v0.4.4 scripts to pick up the Node.js installation, redirect, mirror-index, and Windows PowerShell fixes.
